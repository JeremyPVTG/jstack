# T3 Code integration

T3 Code is jstack's primary host. Skills remain independent of model names, provider accounts, and native agent APIs. Other hosts are optional portability targets.

## Integration contract

Use the current T3 session's supplied instructions and tool schemas. A source snapshot explains the integration but cannot override the installed runtime. Do not bake model IDs, reasoning levels, account preferences, or a provider-specific Skill tool into a reusable skill.

Select a model through T3 when the user or experiment configuration calls for it. Discover current capabilities when the task requires orchestration. Do not turn ordinary research, review, or delivery into delegation merely because T3 supports it. Missing capabilities require an accurate limitation, not an unrequested provider switch or CLI bypass.

Keep T3's current rules for child lifecycle, PR linking and monitoring, secret input, and shared browser interaction in the host. Avoid duplicating those rules in each skill, where they would drift. Project release policy remains in the target project.

## Discovery

T3's skill catalog and model-side discovery are distinct observations. A visible menu item does not prove the selected model loaded its instructions. Record actual discovered name/path, model-side load events where observable, and selected provider adapter.

At the inspected revision, Claude discovery uses its configured user skills root and project .claude/skills, while Cursor scans several provider-style roots. Name precedence also differs. Do not install duplicate names into every directory or assume project copies always take precedence. Inspect collisions before changing links. The existing installer accepts an explicit destination; it does not certify any T3 discovery path.

A model without automatic skill discovery can use an explicit INDEX.md instruction only through its supported mechanism. Record that as an explicit fallback condition, not as native discovery success.
