# Vault access

Use the first that is available.

1. **Vault server** (an MCP server with tools named `guide`, `search`, `read`, `write_page`, `add_to_index`, `capture_source`, `append_log`, `lint`; see [vault-server](../../../vault-server/)). Call `guide` once for the rules. Use `search` and `read` to find pages (`read` `index.md` only to browse the whole vault), `capture_source` for raw sources, `write_page` (with the `sha` from `read`) for wiki pages, `add_to_index` to list each new page in the index, then `append_log` and `lint`. Never rewrite `index.md` to add one line. Works from any device.
2. **Direct access** through a vault checkout, when the vault server is not configured, its sign-in is refused, or its tools fail. If a vault server is configured, call one of its tools by name first (that reconnects a saved sign-in); if it fails, use direct access for the rest of the run without retrying. Before the first vault read or write, say: "The vault MCP server is not available (<reason>), so I am using the vault's git repository directly." Say it again in the report.
   - **Checkout.** Use the local folder (`$J_RESEARCH_VAULT`, else `research_vault` in `~/.config/jstack/config.json`) if set: in a git work tree, run `git pull --rebase --autostash` first; a folder without git is used as is, with no pull or push. Otherwise clone the repository named by `$J_RESEARCH_VAULT_REPO`, else `research_vault_repo` (`owner/name`) in the same config, with `gh repo clone <repo> <dir>` into a new temporary directory (the session's scratch directory if the host has one), and remove it at the end of the run, unless the push failed: then keep it and report its path.
   - **Read.** Read its `AGENTS.md` before writing. Search with `rg` and open each page before citing it.
   - **Write by hand.** Write captures and pages as files following `AGENTS.md`. Add one line per new page to `index.md` under its type's heading, append one line to `log.md` in the `AGENTS.md` format, run `python3 scripts/vault_lint.py <checkout>` from the skill's directory and fix every error, then, in a git work tree, push with `scripts/vault_sync.sh <checkout>` and check that it printed `synced`.
3. **Neither**: research without a vault and offer once to create one from [the template](../assets/vault/).
