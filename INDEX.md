# Skills

Generated by `python3 scripts/check.py --write-index`. Read only the skill relevant to the request.

- [j-bookmarks](skills/j-bookmarks/SKILL.md): Triage saved X (Twitter) bookmarks into a ledger in the research vault, queue the relevant ones for research or as GitHub issues, and work through the queue. Use for "sweep my bookmarks", "what's in my bookmark queue", or "research the bookmark queue".
- [j-build](skills/j-build/SKILL.md): Use this skill to take a bug fix or feature in a code repository from brief to a verified change or draft PR, in stages sized to the task (brief, diagnose, decide, build, review, verify, publish, report), stopping at the first point that needs the owner. Use when asked to build, fix or implement something in a repo, to "follow the workflow", or to "diagnose before changing anything", or when a brief hands over a problem plus constraints. Not for open research questions (j-research), scope decisions (j-scope), or visual and creative design iteration.
- [j-daily](skills/j-daily/SKILL.md): Use this skill when the owner asks what they did today (or on a given day), wants to plan or draft a daily log or blog post about what they learned, or when a scheduled run asks for the daily draft. It gathers the day's research, pull requests, commits and agent conversations, then opens a draft post PR with questions for the owner to answer. Not for writing finished opinion pieces in the owner's name, and not for publishing.
- [j-deliver](skills/j-deliver/SKILL.md): Use this skill when a check or CI run fails on a pull request or branch and must go green, to work an open pull request through conflicts, review threads and CI until it is ready, to publish a finished change (push the exact commit with hooks on and open or update the PR), or to decide whether a PR is ready to merge. Use when a brief says checks failed, CI is red, get it green, fix CI, names a failed run, babysit the PR, address the review comments on PR N, publish, push commit X, test and publish, is PR N ready, or hand off PR N.
- [j-evidence](skills/j-evidence/SKILL.md): Reconcile task completion or public claims against existing evidence. Use for tracker updates, completion checks, or claims review; investigate open questions with j-research.
- [j-research](skills/j-research/SKILL.md): Use this skill before answering any question that depends on facts that can change: versions, prices, limits, best practice, what tools or services exist, whether something is ready for production, whether a vendor, blog or forum claim can be relied on, or how you would build, set up or choose something for the user. It checks the research vault first, searches current sources, and saves what it learns. Training knowledge is not enough for these questions, even when they sound like design advice. Not for code edits, writing, or explaining stable concepts.
- [j-review](skills/j-review/SKILL.md): Use this skill to review a code change and give a verdict, to confirm whether earlier findings are fixed (or refute a new one), to fix supplied findings, or to triage review comments and bot findings on a pull request into fix, dismiss or ask. Use when a brief says review, judge, red team, confirm the fixes, fix round N, address the review comments, or act as the review sub-agent.
- [j-scope](skills/j-scope/SKILL.md): Decide how far to go before building. Draw the MVP line by questioning the user on an honest options brief, and push back on additions that add little. Use after j-research's landscape step, or when asked "how much do we build", "is this overkill", or "what's the MVP".
- [j-skill-audit](skills/j-skill-audit/SKILL.md): Prune or rework agent skills by checking instruction value, overlap, dependencies, and observed task outcomes. Use for skill audits and consolidation, not ordinary code review.
